## 第16回　卫语句与早退

### 第16回　ガード節と早期リターン

------

## 中文版

### 引言

很多时候，函数内部充斥着多层 `if-else` 嵌套，让人难以追踪真正的业务逻辑。
 **卫语句（Guard Clauses）** 与 **早退（Early Return）** 提供了一种简洁的思路：
 把异常或边界情况**优先处理并返回**，让主要逻辑保持直观清晰。

------

### 7.1 卫语句（Guard Clauses）

**定义**：在函数的开头检查不满足条件的情况，立即返回，避免后续嵌套。

**示例（Before → After）**

```
// Before
String getStatus(User? user) {
  if (user != null) {
    if (user.active) {
      if (!user.blocked) {
        return "OK";
      }
    }
  }
  return "NG";
}

// After (卫语句)
String getStatus(User? user) {
  if (user == null) return "NG";
  if (!user.active) return "NG";
  if (user.blocked) return "NG";
  return "OK";
}
```

✅ 好处：减少缩进层级，逻辑路径一目了然。

------

### 7.2 早退（Early Return）

**定义**：当遇到错误或边界条件时，立刻返回，而不是继续执行冗余逻辑。

**示例（Before → After）**

```
// Before
fun process(order: Order?): String {
    if (order != null) {
        if (order.items.isNotEmpty()) {
            return "Processing ${order.items.size} items"
        } else {
            return "Empty order"
        }
    } else {
        return "Invalid order"
    }
}

// After (早退)
fun process(order: Order?): String {
    if (order == null) return "Invalid order"
    if (order.items.isEmpty()) return "Empty order"
    return "Processing ${order.items.size} items"
}
```

✅ 好处：快速终止不符合条件的情况，突出核心逻辑。

------

### 7.3 使用建议

- 函数复杂度大、嵌套层级多时，优先考虑卫语句。
- 对输入数据进行校验时，早退尤其合适。
- 避免过度使用早退，保持函数聚焦单一责任。

------

### 小结

> **卫语句让逻辑扁平化，早退让异常情况更快暴露。**
>  在实际开发中，两者常常一起使用，帮助我们写出更直观、更健壮的代码。

------

## 日本語版

### 序文

多くの関数は `if-else` が入れ子になり、ビジネスロジックが見えにくくなります。
 **ガード節（Guard Clauses）** と **早期リターン（Early Return）** はその解決策です。
 先に例外や境界条件を処理してすぐに戻ることで、メインのロジックをシンプルに保ちます。

------

### 7.1 ガード節（Guard Clauses）

**定義**：関数冒頭で条件を確認し、不成立ならすぐリターンする。

**例（Before → After）**

```
// Before
String getStatus(User? user) {
  if (user != null) {
    if (user.active) {
      if (!user.blocked) {
        return "OK";
      }
    }
  }
  return "NG";
}

// After（ガード節）
String getStatus(User? user) {
  if (user == null) return "NG";
  if (!user.active) return "NG";
  if (user.blocked) return "NG";
  return "OK";
}
```

✅ メリット：インデントが浅くなり、処理の流れが明快になる。

------

### 7.2 早期リターン（Early Return）

**定義**：エラーや境界条件に遭遇した時点で直ちに戻り、余分な処理を避ける。

**例（Before → After）**

```
// Before
fun process(order: Order?): String {
    if (order != null) {
        if (order.items.isNotEmpty()) {
            return "Processing ${order.items.size} items"
        } else {
            return "Empty order"
        }
    } else {
        return "Invalid order"
    }
}

// After（早期リターン）
fun process(order: Order?): String {
    if (order == null) return "Invalid order"
    if (order.items.isEmpty()) return "Empty order"
    return "Processing ${order.items.size} items"
}
```

✅ メリット：条件をすぐに処理するため、主要ロジックが目立つ。

------

### 7.3 利用のヒント

- 関数が複雑で入れ子が深い場合、まずガード節を検討。
- 入力検証の処理に特に効果的。
- 乱用せず、関数の責務を明確に保つことが大切。

------

### まとめ

> **ガード節はロジックを平坦化し、早期リターンは例外処理を前倒しにする。**
>  両者を適切に組み合わせることで、コードはより直感的かつ堅牢になる。
