## 第8回　巨型类与过长参数列表

### 第8回　巨大クラスと長すぎる引数リスト

------

## 中文版

### 引言

如果说 **重复代码** 和 **长函数** 是最常见的异味，那么在 **类级别**，最典型的问题就是：

- **巨型类（Large Class）**
- **过长参数列表（Long Parameter List）**

它们都会让代码的维护成本急剧上升，进而拖慢整个团队的开发效率。

------

### 8.1 巨型类（Large Class）

**特征**：

- 类中有过多的字段和方法。
- 一个类同时负责 UI、业务逻辑、数据库访问等多个职责。
- 修改一处逻辑时，经常会牵动一大堆无关代码。

**示例（Before → After）**

```
// Before：User 类过于臃肿
class User {
  String name;
  String email;
  String address;
  String creditCard;
  String expiry;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
  void charge(double amount) { ... } // 负责支付逻辑
}
// After：提取 BillingInfo 类
class User {
  String name;
  String email;
  String address;
  BillingInfo billing;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
}

class BillingInfo {
  String creditCard;
  String expiry;

  void charge(double amount) { ... }
}
```

✅ 好处：职责分离、逻辑清晰，测试更容易。

------

### 8.2 过长参数列表（Long Parameter List）

**特征**：

- 方法调用时参数超过 4～5 个。
- 参数顺序难记，调用容易出错。
- 很多参数本质上是**相关联的一组数据**。

**示例（Before → After）**

```
// Before：参数太多
fun createUser(name: String, email: String, age: Int, address: String, phone: String) {
    // ...
}
// After：引入参数对象
data class UserProfile(
    val name: String,
    val email: String,
    val age: Int,
    val address: String,
    val phone: String
)

fun createUser(profile: UserProfile) {
    // ...
}
```

✅ 好处：参数传递简洁，语义更清晰，可扩展性强。

------

### 8.3 两者的关系

- **巨型类**：职责过多，需要 **拆分**。
- **过长参数列表**：调用复杂，需要 **封装**。
- 它们都体现了“**结构负担过重**”的问题 → 通过 **提取类 / 参数对象** 来简化。

------

### 小结

- **巨型类** → 提取类，拆分职责。
- **过长参数列表** → 引入参数对象，提升可读性。
   **核心思想**：让代码结构更轻巧，降低维护成本。

------

## 日本語版

### 序文

**重複コード** や **長すぎるメソッド** が典型的な悪臭なら、**クラスレベル** で最もよく見られる問題は：

- **巨大クラス（Large Class）**
- **長すぎる引数リスト（Long Parameter List）**

これらは保守コストを急激に高め、チーム開発全体の効率を下げる原因になります。

------

### 8.1 巨大クラス（Large Class）

**特徴**：

- フィールドやメソッドが多すぎる。
- 1つのクラスが UI・業務ロジック・DB アクセスなど複数の責務を抱えている。
- 1つの変更が多数の無関係なコードに影響する。

**例（Before → After）**

```
// Before：User クラスが肥大化
class User {
  String name;
  String email;
  String address;
  String creditCard;
  String expiry;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
  void charge(double amount) { ... } // 決済ロジックもここにある
}
// After：BillingInfo クラスを抽出
class User {
  String name;
  String email;
  String address;
  BillingInfo billing;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
}

class BillingInfo {
  String creditCard;
  String expiry;

  void charge(double amount) { ... }
}
```

✅ メリット：責務が分離され、構造が明確になり、テストしやすい。

------

### 8.2 長すぎる引数リスト（Long Parameter List）

**特徴**：

- メソッド呼び出し時に引数が4～5個以上。
- 順序を覚えにくく、呼び出しミスが発生しやすい。
- 多くの場合、引数は**関連するデータの集合**。

**例（Before → After）**

```
// Before：引数が多すぎる
fun createUser(name: String, email: String, age: Int, address: String, phone: String) {
    // ...
}
// After：パラメータオブジェクトを導入
data class UserProfile(
    val name: String,
    val email: String,
    val age: Int,
    val address: String,
    val phone: String
)

fun createUser(profile: UserProfile) {
    // ...
}
```

✅ メリット：呼び出しが簡潔になり、意味が明確になり、拡張性も向上。

------

### 8.3 両者の関係

- **巨大クラス** → 責務が多すぎるので **分割** が必要。
- **長すぎる引数リスト** → 呼び出しが複雑なので **カプセル化** が必要。
- 共通する本質は「**構造の重さ**」であり、解決策は **クラス抽出／パラメータオブジェクト導入**。

------

### まとめ

- **巨大クラス** → クラス抽出で責務を分離。
- **長すぎる引数リスト** → パラメータオブジェクトで簡潔化。
   **基本思想**：構造を軽くし、保守性を高めること。
