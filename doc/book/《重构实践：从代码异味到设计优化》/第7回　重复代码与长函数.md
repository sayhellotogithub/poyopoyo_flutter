## 第7回　重复代码与长函数

### 第7回　重複コードと長すぎるメソッド

------

## 中文版

### 引言

在所有的 **代码异味** 中，最常见、最直观的就是 **重复代码** 和 **长函数**。
 它们几乎是“万恶之源”：

- 重复代码 → 增加维护成本，修改容易遗漏。
- 长函数 → 理解困难，测试覆盖不足。

这两种问题常常同时出现，因此重构手法也高度相关：**提取函数（Extract Method）**。

------

### 7.1 重复代码（Duplicated Code）

**特征**：

- 相同或高度相似的逻辑出现在多个地方。
- 一旦需求变更，需要在多个文件/方法中同步修改。

**示例（Before → After）**

```
// Before
double calcTaxA(double price) {
  return price * 0.1;
}

double calcTaxB(double price) {
  return price * 0.1;
}
// After：提取公共函数
double calcTax(double price) => price * 0.1;
```

✅ 好处：单点修改，避免遗漏。

------

### 7.2 长函数（Long Method）

**特征**：

- 一个函数超过几十行甚至上百行。
- 多个逻辑混杂在一起，阅读困难。

**示例（Before → After）**

```
// Before
fun checkout(order: Order) {
    var subtotal = 0.0
    for (item in order.items) {
        subtotal += item.price
    }
    val tax = subtotal * 0.1
    val discount = if (order.customer.level > 3) subtotal * 0.9 else subtotal
    val total = discount + tax
    println("Total: $total")
}
// After：提取函数
fun subtotal(order: Order) = order.items.sumOf { it.price }
fun tax(amount: Double) = amount * 0.1
fun discount(customer: Customer, amount: Double) =
    if (customer.level > 3) amount * 0.9 else amount

fun checkout(order: Order) {
    val sub = subtotal(order)
    val total = discount(order.customer, sub) + tax(sub)
    println("Total: $total")
}
```

✅ 好处：逻辑清晰、可复用、易于测试。

------

### 7.3 重复代码与长函数的关系

- 长函数往往会导致逻辑片段在多个地方被复制粘贴 → 形成重复代码。
- 重复代码积累过多时，也容易被拼凑进一个“长函数”。
   👉 **提取函数** 是二者的共同解法。

------

### 小结

- **重复代码**：修改风险大 → 提取公共方法解决。
- **长函数**：理解困难 → 拆分为小而清晰的函数。
- **核心思路**：**小而清晰的方法 > 冗长而臃肿的方法**。

## 日本語版

### 序文

数ある **コードの悪臭** の中で、最もよく見られるのが **重複コード** と **長すぎるメソッド** です。
 これはまさに「万悪の根源」：

- 重複コード → 保守コストが増え、修正漏れの温床になる。
- 長すぎるメソッド → 読みにくく、テストも困難。

両者はしばしば同時に現れるため、代表的な解決策は **メソッド抽出（Extract Method）** です。

------

### 7.1 重複コード（Duplicated Code）

**特徴**：

- 同じ、または似たようなロジックが複数箇所に存在。
- 要件変更時に、複数箇所を同時に修正する必要がある。

**例（Before → After）**

```
// Before
double calcTaxA(double price) {
  return price * 0.1;
}

double calcTaxB(double price) {
  return price * 0.1;
}
// After：共通メソッドに抽出
double calcTax(double price) => price * 0.1;
```

✅ メリット：修正は1か所のみで済み、漏れを防げる。

------

### 7.2 長すぎるメソッド（Long Method）

**特徴**：

- メソッドが数十行〜百行以上。
- 複数の処理が混在していて読みにくい。

**例（Before → After）**

```
// Before
fun checkout(order: Order) {
    var subtotal = 0.0
    for (item in order.items) {
        subtotal += item.price
    }
    val tax = subtotal * 0.1
    val discount = if (order.customer.level > 3) subtotal * 0.9 else subtotal
    val total = discount + tax
    println("Total: $total")
}
// After：メソッド抽出
fun subtotal(order: Order) = order.items.sumOf { it.price }
fun tax(amount: Double) = amount * 0.1
fun discount(customer: Customer, amount: Double) =
    if (customer.level > 3) amount * 0.9 else amount

fun checkout(order: Order) {
    val sub = subtotal(order)
    val total = discount(order.customer, sub) + tax(sub)
    println("Total: $total")
}
```

✅ メリット：処理が整理され、再利用性・テスト容易性が高まる。

------

### 7.3 重複コードと長すぎるメソッドの関係

- 長すぎるメソッドは、同じロジックのコピペを生みやすい。
- 重複コードが増えると、それをまとめて「長大なメソッド」に押し込めがち。
   👉 **メソッド抽出** が両方の共通解になる。

------

### まとめ

- **重複コード**：修正リスクが高い → 共通メソッドに抽出。
- **長すぎるメソッド**：読みにくい → 小さなメソッドに分割。
- **基本思想**：**小さく明快なメソッド ＞ 冗長で巨大なメソッド**。
