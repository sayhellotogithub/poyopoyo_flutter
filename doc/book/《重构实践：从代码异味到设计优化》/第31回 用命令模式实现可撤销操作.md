# **第31回 用命令模式实现可撤销操作**

## 1. 背景与问题

许多交互/业务需要**撤销（Undo）\**与\**重做（Redo）**：

- 文本/图形编辑：插入、删除、移动、缩放、颜色修改
- 订单流程：提交→撤回→再次提交（需保证一致性）
- 后台运营：批量上下架、调价回退、误操作恢复

若直接把撤销逻辑塞进业务类中，会导致：

- 方法暴涨、状态回滚分散且脆弱
- 难以扩展新操作；耦合度高、测试困难
- 副作用操作（网络/IO）回滚语义不清晰

**命令模式（Command Pattern）** 通过将“操作”抽象为对象，并把**执行**与**撤销**统一封装，实现**解耦、可组合、可记录、可回放**。

------

## 2. 核心思路

- **Command**：抽象一条操作，提供 `execute()` / `undo()`（如需 `redo()` 则通常等价于再次 `execute()` 或专门实现）。
- **Receiver**：真正干活的对象（编辑器、画布、订单服务等）。
- **Invoker**：触发命令执行，并维护历史栈（undoStack/redoStack）。
- **Client**：装配命令与接收者。
- 可扩展：**宏命令（Macro）**、**队列命令（异步/重试）**、**事务性命令（结合补偿）**。

------

## 4. 代码示例

### 4.1 Java：文本编辑器的插入/删除可撤销

```
// Command 接口
public interface Command {
    void execute();
    void undo();
}

// Receiver：简化的文本缓冲区
public class TextBuffer {
    private final StringBuilder sb = new StringBuilder();
    public void insert(int pos, String text) { sb.insert(pos, text); }
    public void delete(int start, int end) { sb.delete(start, end); }
    public String getText() { return sb.toString(); }
}

// 具体命令：插入
public class InsertCommand implements Command {
    private final TextBuffer buffer;
    private final int pos;
    private final String text;

    public InsertCommand(TextBuffer buffer, int pos, String text) {
        this.buffer = buffer;
        this.pos = pos;
        this.text = text;
    }

    @Override public void execute() { buffer.insert(pos, text); }
    @Override public void undo() { buffer.delete(pos, pos + text.length()); }
}

// 具体命令：删除
public class DeleteCommand implements Command {
    private final TextBuffer buffer;
    private final int start;
    private final int end;
    private String deleted; // 用于撤销恢复

    public DeleteCommand(TextBuffer buffer, int start, int end) {
        this.buffer = buffer;
        this.start = start;
        this.end = end;
    }

    @Override public void execute() {
        String current = buffer.getText();
        deleted = current.substring(start, end);
        buffer.delete(start, end);
    }

    @Override public void undo() {
        buffer.insert(start, deleted);
    }
}

// Invoker：维护历史栈
import java.util.ArrayDeque;
import java.util.Deque;

public class CommandInvoker {
    private final Deque<Command> undoStack = new ArrayDeque<>();
    private final Deque<Command> redoStack = new ArrayDeque<>();

    public void invoke(Command cmd) {
        cmd.execute();
        undoStack.push(cmd);
        redoStack.clear(); // 新分支，重做栈清空
    }

    public boolean canUndo() { return !undoStack.isEmpty(); }
    public boolean canRedo() { return !redoStack.isEmpty(); }

    public void undo() {
        if (!canUndo()) return;
        Command c = undoStack.pop();
        c.undo();
        redoStack.push(c);
    }

    public void redo() {
        if (!canRedo()) return;
        Command c = redoStack.pop();
        c.execute();
        undoStack.push(c);
    }
}

// 演示
public class Demo {
    public static void main(String[] args) {
        TextBuffer buffer = new TextBuffer();
        CommandInvoker invoker = new CommandInvoker();

        invoker.invoke(new InsertCommand(buffer, 0, "Hello"));
        invoker.invoke(new InsertCommand(buffer, 5, " World"));
        System.out.println(buffer.getText()); // Hello World

        invoker.undo();
        System.out.println(buffer.getText()); // Hello

        invoker.redo();
        System.out.println(buffer.getText()); // Hello World

        invoker.invoke(new DeleteCommand(buffer, 5, 11));
        System.out.println(buffer.getText()); // Hello
        invoker.undo();
        System.out.println(buffer.getText()); // Hello World
    }
}
```

#### 要点

- `DeleteCommand` 在 `execute()` 中**捕获被删片段**，以便 `undo()` 恢复。
- `Invoker` 维护 **undo/redo 两个栈**。新命令执行后，**清空 redo 栈**（分叉的时间线）。
- 业务扩展时，只需添加新命令类，不影响已有命令与调用方。

### 4.2 Dart/Flutter：画布形状移动的可撤销

```
abstract class Command {
  void execute();
  void undo();
}

class Shape {
  Offset position;
  Shape(this.position);
}

class MoveCommand implements Command {
  final Shape shape;
  final Offset delta;
  late final Offset _before, _after;

  MoveCommand(this.shape, this.delta);

  @override
  void execute() {
    _before = shape.position;
    _after = shape.position + delta;
    shape.position = _after;
  }

  @override
  void undo() {
    shape.position = _before;
  }
}

class CommandInvoker {
  final List<Command> _undo = [];
  final List<Command> _redo = [];

  void invoke(Command c) {
    c.execute();
    _undo.add(c);
    _redo.clear();
  }

  bool get canUndo => _undo.isNotEmpty;
  bool get canRedo => _redo.isNotEmpty;

  void undo() {
    if (!canUndo) return;
    final c = _undo.removeLast();
    c.undo();
    _redo.add(c);
  }

  void redo() {
    if (!canRedo) return;
    final c = _redo.removeLast();
    c.execute();
    _undo.add(c);
  }
}
```

UI 层只需把按钮事件映射到 `invoke/undo/redo`，Widget 通过 `setState`/`Notifier` 刷新位置即可。命令对象携带必要的“前/后”状态，独立且可测试。

## 5. 宏命令、队列与事务

### 宏命令（Macro）

将多条命令**组合**为一个命令：

- `execute()` 依序执行子命令；
- `undo()` 按**逆序**撤销，确保一致性。
   适合**批量修改**、**多人协作的合并操作**等。

### 队列命令（异步/重试）

- 将命令排入队列（本地/分布式），由工作器执行；
- 失败可重试或记录死信；
- 需要**幂等性**保证（例如使用业务幂等键）。

### 事务性命令 & 补偿

- 单体服务可借助本地事务；
- 分布式场景采用 **补偿事务（Saga/补偿命令）**：
  - `execute()` 完成正向动作；
  - `undo()` 执行**补偿动作**（非简单反操作）。
- 对于**不可逆副作用**（发邮件、外部支付），撤销通常是**补发相反业务事件**（如“退款”），而非“抹去历史”。

------

## 6. 与备忘录（Memento）的对比

- **命令模式**：关注“操作”，通过 `undo()` 逆向变更；状态快照最小化（只保存必要差异）。
- **备忘录模式**：关注“状态”，在变更前保存对象完整快照，回滚时整体还原。
- 实战中常结合：**命令 + 局部快照**，在复杂对象上既能可靠回滚又不至于过度拷贝。

------

## 7. 重构步骤建议

1. **识别操作点**：找出需要可撤销的核心操作（编辑、流程、配置修改…）。
2. **抽象 Command**：为每类操作建一个命令类，明确 `execute/undo` 的**最小必要状态**。
3. **抽离 Receiver**：把具体业务动作放进接收者，命令只做协调与数据承载。
4. **引入 Invoker**：集中维护历史栈/重做栈、宏命令、快捷键映射等。
5. **幂等与一致性**：为跨进程/网络的命令设计幂等键、补偿语义与重试策略。
6. **测试**：对每个命令编写**执行-撤销-重做**的单测；引入**宏命令逆序撤销**用例。

------

## 8. 适用与不适用

**适用：**

- 需要 Undo/Redo；
- 操作可被记录、回放、脚本化；
- 希望将 UI 与业务动作彻底解耦；
- 批量/宏处理、历史追溯。

**不适用：**

- 操作不可逆且无补偿语义；
- 超高频微操作但无需撤销（命令对象创建开销得不偿失）；
- 状态极其庞大且更适合**整快照还原**（可考虑备忘录或事件溯源）。

------

## 9. 测试清单（Checklist）

- `execute()` 与 `undo()` 是否对称？是否有**遗漏的边界状态**？
- 新命令执行后**清空 redo 栈**？
- 宏命令 `undo()` 是否严格**逆序**？
- 幂等：重复执行/撤销是否安全？
- 跨服务：是否定义了补偿命令与失败策略？
- 性能：命令对象的状态保存是否**最小化**？

------

## 10. 小结

命令模式把“动作”封装成对象，统一了**执行/撤销/重做/记录/组合**等能力：

- 解耦 UI 与业务操作
- 自然支持历史栈与宏命令
- 可扩展到异步队列与分布式补偿



# **第31回 コマンドパターンで取り消し可能な操作を実現する**

------

## **1. 背景と問題**

多くのアプリケーションでは **取り消し（Undo）** や **やり直し（Redo）** が必要になります：

- テキスト／図形編集：挿入、削除、移動、拡大縮小、色変更
- 注文処理：提出 → 取り消し → 再提出
- 管理画面：商品の一括公開・非公開、価格改定の巻き戻し

もし取り消し処理を直接ビジネスロジックに埋め込むと：

- メソッドが肥大化し、状態の巻き戻しが脆弱
- 新しい操作を追加しにくい（強結合）
- 副作用（ネットワーク／IO）を含む場合、ロールバックが不明確

**コマンドパターン（Command Pattern）** を使えば、操作をオブジェクト化し、
 `execute()` と `undo()` を統一的に扱うことで **疎結合・拡張性・再利用性・履歴管理** を実現できます。

------

## **2. コアアイデア**

- **Command**：操作を抽象化し、`execute()`／`undo()` を定義
- **Receiver**：実際の処理を行うオブジェクト（テキストバッファ、キャンバス、注文サービスなど）
- **Invoker**：コマンドを実行し、Undo／Redo のスタックを管理
- **Client**：コマンドとレシーバーを組み合わせる

拡張例：

- **マクロコマンド**：複数の操作をひとまとめに実行／取り消し
- **キューコマンド**：非同期処理やリトライに利用
- **補償コマンド**：分散トランザクションでの取り消し処理

------

### Java：テキストバッファの挿入／削除を取り消し可能に

```

    void undo();
}

        this.text = text;

    @Override public void undo() { buffer.delete(pos, pos + text.length()); }
}

    private final TextBuffer buffer;
    private final int start;
    private final int end;
    private String deleted;

    public DeleteCommand(TextBuffer buffer, int start, int end) {

        this.start = start;
        this.end = end;
    }

    @Override public void execute() {
        String current = buffer.getText();
        deleted = current.substring(start, end);
        buffer.delete(start, end);
    }

    @Override public void undo() {
        buffer.insert(start, deleted);

// Invoker：履歴管理
import java.util.ArrayDeque;
import java.util.Deque;

    private final Deque<Command> undoStack = new ArrayDeque<>();
    private final Deque<Command> redoStack = new ArrayDeque<>();

    public void invoke(Command cmd) {
        cmd.execute();
        undoStack.push(cmd);
        redoStack.clear();
```

## **5. 拡張：マクロ・キュー・補償**

- **マクロコマンド**：複数のコマンドをまとめて実行／逆順で取り消し
- **キューコマンド**：非同期実行やリトライに利用
- **補償コマンド**：分散システムでの取り消しに利用（例：注文キャンセル→返金コマンド）

------

## **6. メメントパターンとの比較**

- **コマンドパターン**：操作を記録し、`undo()` で逆操作を実行
- **メメントパターン**：状態をスナップショットとして保存し、復元
- 実務では **コマンド＋部分的メメント** を組み合わせて使うことも多い

------

## **7. 適用シーン**

**向いているケース**

- Undo／Redo が必要なアプリ
- 操作の記録・再生・スクリプト化
- UI とビジネスロジックを疎結合にしたい場合

**向いていないケース**

- 操作が不可逆で補償不能
- 高頻度で軽量な操作（オブジェクト生成コストが無駄）
- 状態が巨大で、丸ごとスナップショットの方が効率的な場合

------

## **まとめ**

コマンドパターンは操作をオブジェクトとして抽象化することで：

- **実行／取り消し／やり直し** を統一的に扱える
- 履歴管理・マクロ・非同期処理に拡張しやすい
- UI とビジネスロジックをきれいに分離できる

 バリデーションやリクエスト処理を「チェーン構造」で拡張可能にする設計を解説します。
