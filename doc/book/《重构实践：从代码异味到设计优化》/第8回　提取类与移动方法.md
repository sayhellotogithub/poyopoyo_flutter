## 第8回　提取类与移动方法

### 第8回　クラス抽出とメソッド移動

------

## 中文版

### 引言

当一个类承担了太多职责时，它会变成所谓的“**巨型类（Large Class）**”。
 这种类往往代码量庞大、方法过多、逻辑杂糅，不仅难以理解，还会导致测试困难。
 解决这一问题的常见手法就是：**提取类（Extract Class）** 和 **移动方法（Move Method）**。

------

### 8.1 提取类（Extract Class）

**适用场景**

- 类中方法过多，职责分散。
- 属性呈现明显分组（例如用户信息 vs 账单信息）。
- 修改一个功能常常影响到多个无关字段。

**示例（Before → After）**

```
// Before：User 类过于臃肿
class User {
  String name;
  String email;
  String address;
  String creditCard;
  String expiry;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
  void charge(double amount) { ... }
}
// After：提取 BillingInfo 类
class User {
  String name;
  String email;
  String address;
  BillingInfo billing;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
}

class BillingInfo {
  String creditCard;
  String expiry;

  void charge(double amount) { ... }
}
```

✅ 好处：**高内聚、低耦合**，User 负责用户资料，BillingInfo 专注支付。

------

### 8.2 移动方法（Move Method）

**适用场景**

- 某个方法频繁操作另一个类的数据。
- 方法放在当前类中“不自然”，更适合属于另一个类。
- Feature Envy（特性嫉妒）的典型表现。

**示例（Before → After）**

```
// Before：Order 类中方法依赖 Customer 数据
class Customer(val name: String, val level: Int)

class Order(val amount: Double, val customer: Customer) {
    fun discount(): Double {
        return if (customer.level > 3) amount * 0.9 else amount
    }
}
// After：将 discount 方法移到 Customer
class Customer(val name: String, val level: Int) {
    fun discount(amount: Double): Double {
        return if (level > 3) amount * 0.9 else amount
    }
}

class Order(val amount: Double, val customer: Customer) {
    fun finalPrice(): Double = customer.discount(amount)
}
```

✅ 好处：逻辑更自然，方法归属合理，减少类间耦合。

------

### 8.3 使用建议

- **提取类**：当一个类的字段和方法数量过多时。
- **移动方法**：当方法对另一个类“更有亲和性”时。
- 结合使用时，可以逐步把“巨型类”拆解为多个小而清晰的类。

------

### 小结

- **提取类** → 解决巨型类问题，让职责更清晰。
- **移动方法** → 解决方法归属不当的问题，让逻辑更合理。
   两者配合使用，是应对“类级别异味”的基本武器。

------

## 日本語版

### 序文

1つのクラスがあまりにも多くの責務を抱えると、いわゆる「**巨大クラス（Large Class）**」になってしまいます。
 コード量が膨大で、メソッドが乱立し、理解もテストも難しくなるのです。
 この問題を解決する代表的な手法が **クラス抽出（Extract Class）** と **メソッド移動（Move Method）** です。

------

### 8.1 クラス抽出（Extract Class）

**適用場面**

- クラス内のメソッドが多すぎて責務が分散している。
- フィールドがグループ化されている（例：ユーザー情報と請求情報）。
- 1つの機能を変更する際に複数の無関係なフィールドが影響を受ける。

**例（Before → After）**

```
// Before：User クラスが肥大化
class User {
  String name;
  String email;
  String address;
  String creditCard;
  String expiry;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
  void charge(double amount) { ... }
}
// After：BillingInfo クラスを抽出
class User {
  String name;
  String email;
  String address;
  BillingInfo billing;

  void updateProfile(String newName, String newEmail) { ... }
  void updateAddress(String newAddress) { ... }
}

class BillingInfo {
  String creditCard;
  String expiry;

  void charge(double amount) { ... }
}
```

✅ メリット：**高凝集・低結合**。User はユーザー情報、BillingInfo は決済に専念できる。

------

### 8.2 メソッド移動（Move Method）

**適用場面**

- あるメソッドが頻繁に別クラスのデータを操作している。
- メソッドの存在場所が「不自然」で、別のクラスにある方が自然。
- Feature Envy（特性嫉妬）の典型的な兆候。

**例（Before → After）**

```
// Before：Order のメソッドが Customer データに依存
class Customer(val name: String, val level: Int)

class Order(val amount: Double, val customer: Customer) {
    fun discount(): Double {
        return if (customer.level > 3) amount * 0.9 else amount
    }
}
// After：discount メソッドを Customer に移動
class Customer(val name: String, val level: Int) {
    fun discount(amount: Double): Double {
        return if (level > 3) amount * 0.9 else amount
    }
}

class Order(val amount: Double, val customer: Customer) {
    fun finalPrice(): Double = customer.discount(amount)
}
```

✅ メリット：ロジックが自然になり、メソッドの責務が適切なクラスに属するようになる。

------

### 8.3 利用のヒント

- **クラス抽出**：クラスが肥大化したとき。
- **メソッド移動**：メソッドが他クラスと強く結びついているとき。
- 両者を組み合わせれば、「巨大クラス問題」を段階的に解消できる。

------

### まとめ

- **クラス抽出** → 巨大クラスを解体し、責務を明確化する。
- **メソッド移動** → メソッドの帰属を適正化し、クラス間の結合度を下げる。
   クラスレベルの悪臭を解消するための基本的な武器である。
