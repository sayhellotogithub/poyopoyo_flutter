## 第29回　从重复代码到模板方法模式

### 第29回　重複コードからテンプレートメソッドパターンへ

------

## 中文版

### 背景

重复代码（Duplicated Code）是最常见的代码异味：

- 多个方法中只有少部分逻辑不同，其余完全相同。
- 复制粘贴的逻辑导致后期维护困难（改一处要改多处）。
- 逻辑分散，不利于测试与扩展。

👉 解决方案之一：**模板方法模式**。

------

### 29.1 重复代码示例

```
class CSVParser {
    public void parse(String file) {
        System.out.println("读取文件: " + file);
        System.out.println("按行解析 CSV");
        System.out.println("处理结果");
    }
}

class JSONParser {
    public void parse(String file) {
        System.out.println("读取文件: " + file);
        System.out.println("按行解析 JSON");
        System.out.println("处理结果");
    }
}
```

问题：

- `读取文件` 与 `处理结果` 完全相同，
- 唯一区别是 **“如何解析”**。

------

### 29.2 模板方法模式重构

```
abstract class FileParser {
    public final void parse(String file) {
        System.out.println("读取文件: " + file);
        doParse(file);   // 变化点
        System.out.println("处理结果");
    }

    protected abstract void doParse(String file);
}

class CSVParser extends FileParser {
    @Override
    protected void doParse(String file) {
        System.out.println("按行解析 CSV");
    }
}

class JSONParser extends FileParser {
    @Override
    protected void doParse(String file) {
        System.out.println("按行解析 JSON");
    }
}
```

✅ 好处：

- 公共逻辑抽取到基类，避免重复。
- 不同逻辑交由子类实现，符合开闭原则。

------

### 29.3 适用场景

- 多个子类逻辑类似，仅部分步骤不同。
- 需要统一骨架流程，允许部分步骤延迟到子类。
- 常见场景：解析器、导出器、算法流程（如排序、报表生成）。

------

### 小结

- **重复代码** → 难以维护，易产生错误。
- **模板方法模式** → 提取公共流程，变化点交给子类。
- 本质：**用继承来消除重复，用抽象方法保留扩展点**。

------

## 日本語版

### はじめに

重複コード（Duplicated Code）は最も一般的なコードスメルの一つ：

- 複数メソッドで大部分は同じ処理、ほんの一部だけ異なる。
- コピペにより修正時に同じ変更を複数箇所へ適用しなければならない。
- ロジックが分散し、テストや拡張が困難。

👉 解決策の一つが **テンプレートメソッドパターン**。

------

### 29.1 重複コードの例

```
class CSVParser {
    public void parse(String file) {
        System.out.println("ファイル読込: " + file);
        System.out.println("CSV 行単位で解析");
        System.out.println("結果を処理");
    }
}

class JSONParser {
    public void parse(String file) {
        System.out.println("ファイル読込: " + file);
        System.out.println("JSON 行単位で解析");
        System.out.println("結果を処理");
    }
}
```

------

### 29.2 テンプレートメソッドパターンによるリファクタリング

```
abstract class FileParser {
    public final void parse(String file) {
        System.out.println("ファイル読込: " + file);
        doParse(file);   // 差分部分
        System.out.println("結果を処理");
    }

    protected abstract void doParse(String file);
}

class CSVParser extends FileParser {
    @Override
    protected void doParse(String file) {
        System.out.println("CSV 行単位で解析");
    }
}

class JSONParser extends FileParser {
    @Override
    protected void doParse(String file) {
        System.out.println("JSON 行単位で解析");
    }
}
```

✅ メリット：

- 共通処理を基底クラスに集約し、重複を排除。
- 変化する処理をサブクラスに委ね、拡張に強い。

------

### 29.3 適用シナリオ

- 複数のサブクラスが似た処理を持ち、一部だけ異なる場合。
- 骨格処理を統一し、一部のステップをサブクラスに委譲したい場合。
- 例：パーサー、エクスポーター、アルゴリズムフロー（ソート、レポート生成）。

------

### まとめ

- **重複コード** → 保守性を下げる。
- **テンプレートメソッドパターン** → 共通処理を抽出し、差分をサブクラスに委譲。
- 本質：**継承で重複を排除し、抽象メソッドで拡張性を確保する**。

# 重复代码 → 重构手法对照表（中文版）

| 场景             | 典型问题                                     | 重构手法                                    | 示例                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------- | -------------------------------------- |
| **局部重复**     | 方法内部有几行重复逻辑                       | **提炼方法（Extract Method）**              | 提取为 `validateInput()`、`logError()` |
| **跨类重复**     | 多个子类有相似逻辑，大部分相同，只有部分不同 | **模板方法模式（Template Method Pattern）** | 文件解析器、报表生成器                 |
| **逻辑可互换**   | 分支逻辑不同但可替换                         | **策略模式（Strategy Pattern）**            | 折扣算法、排序方式                     |
| **工具方法复用** | 不同模块反复使用相同的函数                   | **提炼公共类/工具类**                       | StringUtils、DateUtils                 |

👉 总结：

- **小范围重复** → 提炼方法。
- **流程相同但部分不同** → 模板方法模式。
- **可替换算法/行为** → 策略模式。
- **通用逻辑** → 公共类。

# 📑 重複コード → リファクタリング手法対応表（日文版）

| シナリオ               | 問題点                                         | リファクタリング手法               | 例                              |
| ---------------------- | ---------------------------------------------- | ---------------------------------- | ------------------------------- |
| **ローカルな重複**     | メソッド内で同じ処理が数行繰り返される         | **メソッド抽出（Extract Method）** | `validateInput()`、`logError()` |
| **クラス間の重複**     | 複数サブクラスで処理がほぼ同じ、一部だけ異なる | **テンプレートメソッドパターン**   | ファイルパーサー、レポート生成  |
| **切替可能なロジック** | 分岐ごとに異なるアルゴリズム                   | **ストラテジーパターン**           | 割引計算、ソート方式            |
| **共通ユーティリティ** | 複数モジュールで同じ関数を使う                 | **共通クラス／ユーティリティ抽出** | StringUtils、DateUtils          |

👉 まとめ：

- **小規模な重複** → メソッド抽出。
- **処理の流れが共通だが一部異なる** → テンプレートメソッド。
- **アルゴリズムが差し替え可能** → ストラテジー。
- **共通処理** → ユーティリティ化。
