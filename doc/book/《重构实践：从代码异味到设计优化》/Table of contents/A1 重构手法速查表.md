# 附録 A1　リファクタリング手法早見表

| カテゴリ           | 手法                                                         | 説明                                           |
| ------------------ | ------------------------------------------------------------ | ---------------------------------------------- |
| **メソッドレベル** | メソッド抽出（Extract Method）                               | 長いメソッドや重複コードを切り出す             |
|                    | メソッドインライン化（Inline Method）                        | 不要なメソッド呼び出しを削除し、本体を直接展開 |
|                    | 変数抽出（Introduce Explaining Variable）                    | 複雑な式を説明用変数に置き換え可読性を高める   |
|                    | 一時変数の置換（Replace Temp with Query）                    | 再利用可能な式をメソッド化して再利用           |
|                    | ガード節導入（Introduce Guard Clauses）                      | ネストした条件を早期リターンで整理             |
| **クラスレベル**   | クラス抽出（Extract Class）                                  | 責務過多のクラスを分割                         |
|                    | メソッド移動（Move Method）                                  | 不適切に配置されたメソッドを適切なクラスへ     |
|                    | フィールド移動（Move Field）                                 | データをより自然に扱うクラスへ移動             |
|                    | パラメータオブジェクト導入（Introduce Parameter Object）     | 長すぎる引数リストをオブジェクトにまとめる     |
|                    | 値オブジェクト導入（Introduce Value Object）                 | 基本型執着をドメインを表す型に置換             |
|                    | コレクションのカプセル化（Encapsulate Collection）           | 外部から直接操作されないように集合をカプセル化 |
| **条件・制御構造** | 条件分解（Decompose Conditional）                            | 複雑な条件式をメソッドに分解                   |
|                    | ポリモーフィズムによる置換（Replace Conditional with Polymorphism） | 条件分岐を多態に置き換える                     |
|                    | ストラテジーパターン導入                                     | 動的にアルゴリズムを切り替える                 |
|                    | ステートパターン導入                                         | 状態に応じた振る舞いを分離                     |
| **データ・API**    | データクラス抽出                                             | データ泥団を独立クラス化                       |
|                    | DTO ↔ Entity マッピング                                      | API 仕様変更時の適応層を導入                   |
|                    | インターフェース抽出（Extract Interface）                    | 実装から抽象を分離しテスト容易性を高める       |
| **依存関係・構造** | 依存性注入（Dependency Injection）                           | グローバル依存を排除しテスト容易にする         |
|                    | ファサード導入（Introduce Facade）                           | 複雑なサブシステムに対する単純な窓口を提供     |
|                    | アンチコラプションレイヤー（ACL）                            | 外部システム依存を隔離し影響を防ぐ             |
| **不要な要素整理** | デッドコード削除                                             | 使用されないメソッドや変数を削除               |
|                    | 不要な抽象削除（Remove Speculative Generality）              | 使われていない設計や過剰抽象を整理             |
