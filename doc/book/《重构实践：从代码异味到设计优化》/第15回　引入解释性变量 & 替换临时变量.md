## 第15回　引入解释性变量 & 替换临时变量

### 第15回　説明変数の導入 & 一時変数の置換

------

## 中文版

### 引言

在方法级别的重构中，除了 **提取函数** 与 **内联函数**，还有两种常见手法：

- **引入解释性变量（Introduce Explaining Variable）**
- **替换临时变量（Replace Temp with Query）**

它们的目标都是：让代码**更易读、更少重复**。

------

### 6.1 引入解释性变量（Introduce Explaining Variable）

**适用场景**

- 表达式过长，逻辑晦涩。
- 多层嵌套，难以一眼看懂。
- 需要通过**命名**来解释意图。

**示例（Before → After）**

```
// Before
bool isEligible(User u) {
  return u.age > 18 && u.score > 70 && u.isActive && !u.isBlocked;
}

// After (引入解释性变量)
bool isEligible(User u) {
  final isAdult = u.age > 18;
  final isQualified = u.score > 70;
  final isValid = u.isActive && !u.isBlocked;
  return isAdult && isQualified && isValid;
}
```

✅ 好处：用有意义的变量名替代复杂逻辑，意图更清晰。

------

### 6.2 替换临时变量（Replace Temp with Query）

**适用场景**

- 临时变量保存的是一个可以随时计算的值。
- 相同的计算逻辑在多个地方重复使用。
- 希望通过提取方法提高复用性。

**示例（Before → After）**

```
// Before
fun getTotal(order: Order): Double {
    val subtotal = order.items.sumOf { it.price }
    val tax = subtotal * 0.1
    return subtotal + tax
}

// After (替换临时变量，用方法查询代替)
fun Order.subtotal() = items.sumOf { it.price }
fun Order.tax() = subtotal() * 0.1
fun Order.total() = subtotal() + tax()
```

✅ 好处：逻辑可复用、测试更独立，避免在不同地方写重复的临时变量计算。

------

### 6.3 两者的关系

- **引入解释性变量**：适合在函数内部，用命名来说明复杂逻辑。
- **替换临时变量**：适合抽取成方法/属性，让逻辑可复用。

一句口诀：

> **变量 → 解释；方法 → 复用。**

------

### 小结

- **引入解释性变量**：让复杂表达式更易懂。
- **替换临时变量**：把可复用的计算逻辑提炼成方法，减少重复。
   这两种手法结合使用，可以显著提升代码的**可读性**与**复用性**。

## 日本語版

### 序文

メソッドレベルのリファクタリングには、**メソッド抽出／インライン化**以外にもよく使う手法があります：

- **説明変数の導入（Introduce Explaining Variable）**
- **一時変数の置換（Replace Temp with Query）**

どちらも目的は「コードを読みやすく、重複を減らす」ことです。

------

### 6.1 説明変数の導入（Introduce Explaining Variable）

**適用場面**

- 式が長く、ロジックが読みにくい。
- 入れ子が深く、一目で理解できない。
- **名前をつけることで意図を説明**したい場合。

**例（Before → After）**

```
// Before
bool isEligible(User u) {
  return u.age > 18 && u.score > 70 && u.isActive && !u.isBlocked;
}

// After（説明変数導入）
bool isEligible(User u) {
  final isAdult = u.age > 18;
  final isQualified = u.score > 70;
  final isValid = u.isActive && !u.isBlocked;
  return isAdult && isQualified && isValid;
}
```

✅ メリット：意味のある変数名で複雑なロジックを分解し、意図が明確になる。

------

### 6.2 一時変数の置換（Replace Temp with Query）

**適用場面**

- 一時変数が計算結果を保持しているだけ。
- 同じ計算が複数箇所で繰り返されている。
- メソッド化して再利用性を高めたい。

**例（Before → After）**

```
// Before
fun getTotal(order: Order): Double {
    val subtotal = order.items.sumOf { it.price }
    val tax = subtotal * 0.1
    return subtotal + tax
}

// After（一時変数の置換、メソッド化）
fun Order.subtotal() = items.sumOf { it.price }
fun Order.tax() = subtotal() * 0.1
fun Order.total() = subtotal() + tax()
```

✅ メリット：ロジックを再利用でき、テストもしやすくなる。同じ計算を繰り返さない。

------

### 6.3 両者の関係

- **説明変数の導入**：メソッド内の複雑な式を理解しやすくする。
- **一時変数の置換**：再利用できるロジックをメソッド化する。

ひと言で：

> **変数は説明、メソッドは再利用。**

------

### まとめ

- **説明変数の導入**：複雑な式をわかりやすく分解する。
- **一時変数の置換**：計算ロジックをメソッドにし、重複をなくす。
   この2つを組み合わせることで、コードの**可読性**と**再利用性**を大きく高められる。
