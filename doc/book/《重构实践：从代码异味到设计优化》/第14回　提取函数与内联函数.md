## 第14回　提取函数与内联函数

### 第14回　メソッド抽出とメソッドインライン化

------

## 中文版

### 引言

在重构的诸多手法中，**提取函数（Extract Method）** 和 **内联函数（Inline Method）** 是最常见、最基础的两种。
 它们就像“拆分”和“合并”的双工具：

- 当代码过长、逻辑混乱 → **提取函数**
- 当函数过度碎片化、不再有存在意义 → **内联函数**

------

### 5.1 提取函数（Extract Method）

**适用场景**：

- 函数太长，难以阅读
- 某段逻辑可以独立理解
- 重复代码出现多次

**示例（Before → After）**

```
// Before
void checkout(Order order) {
  // 税额计算
  final tax = order.items.fold<double>(0, (s, it) => s + it.price) * 0.1;
  // 总价计算
  final total = order.items.fold<double>(0, (s, it) => s + it.price) + tax;
  print("Charge: $total");
}

// After (提取函数)
double _subtotal(List<Item> items) =>
    items.fold<double>(0, (s, it) => s + it.price);

double _tax(double subtotal) => subtotal * 0.1;

void checkout(Order order) {
  final subtotal = _subtotal(order.items);
  final total = subtotal + _tax(subtotal);
  print("Charge: $total");
}
```

✅ 好处：逻辑分层更清晰，复用性提高，测试更容易。

------

### 5.2 内联函数（Inline Method）

**适用场景**：

- 函数体代码过于简单，调用反而增加理解成本
- 过度抽象导致阅读断裂
- 提取出来的函数已失去价值

**示例（Before → After）**

```
// Before
fun isActive(u: User): Boolean {
    return u != null && u.active && !u.blocked
}

fun showStatus(u: User) {
    if (isActive(u)) {
        println("OK")
    } else {
        println("NG")
    }
}

// After (内联函数)
fun showStatus(u: User?) {
    if (u != null && u.active && !u.blocked) {
        println("OK")
    } else {
        println("NG")
    }
}
```

✅ 好处：减少不必要的跳转，保持代码直观。

------

### 5.3 如何选择？

- **提取函数**：当逻辑需要被“命名”，帮助理解。
- **内联函数**：当函数名不能比代码本身更清晰时。

一句口诀：

> **提取是为了说明，内联是为了简化。**

------

### 小结

- **提取函数**：对付长函数、重复代码 → 提高清晰度
- **内联函数**：对付过度抽象、无意义封装 → 提高直观性
   在实际重构中，两者经常结合使用，形成 **拆分–合并的动态平衡**。

## 日本語版

### 序文

数あるリファクタリング手法の中でも、**メソッド抽出（Extract Method）** と **メソッドインライン化（Inline Method）** は最も基本的かつ頻出するものです。
 これは「分割」と「統合」の二つの道具のような存在です：

- コードが長く複雑なとき → **メソッド抽出**
- メソッドが細かくなりすぎ意味を失ったとき → **メソッドインライン化**

------

### 5.1 メソッド抽出（Extract Method）

**適用場面**：

- メソッドが長すぎて読みにくい
- ある部分の処理が独立して理解できる
- 同じコードが複数箇所に存在する

**例（Before → After）**

```
// Before
void checkout(Order order) {
  // 税金計算
  final tax = order.items.fold<double>(0, (s, it) => s + it.price) * 0.1;
  // 合計計算
  final total = order.items.fold<double>(0, (s, it) => s + it.price) + tax;
  print("Charge: $total");
}

// After（メソッド抽出）
double _subtotal(List<Item> items) =>
    items.fold<double>(0, (s, it) => s + it.price);

double _tax(double subtotal) => subtotal * 0.1;

void checkout(Order order) {
  final subtotal = _subtotal(order.items);
  final total = subtotal + _tax(subtotal);
  print("Charge: $total");
}
```

✅ メリット：処理が整理され再利用しやすく、テストもしやすくなる。

------

### 5.2 メソッドインライン化（Inline Method）

**適用場面**：

- メソッドが単純すぎて、呼び出し自体が余計
- 抽象が過剰で、コード理解を妨げている
- 抽出したメソッドが価値を失った

**例（Before → After）**

```
// Before
fun isActive(u: User): Boolean {
    return u != null && u.active && !u.blocked
}

fun showStatus(u: User) {
    if (isActive(u)) {
        println("OK")
    } else {
        println("NG")
    }
}

// After（インライン化）
fun showStatus(u: User?) {
    if (u != null && u.active && !u.blocked) {
        println("OK")
    } else {
        println("NG")
    }
}
```

✅ メリット：不要なジャンプが減り、直感的に理解できる。

------

### 5.3 どう選ぶ？

- **メソッド抽出**：処理に名前を与え、理解を助けたいとき。
- **メソッドインライン化**：コード自体が名前以上に明快なとき。

ひと言で：

> **抽出は説明のため、インライン化は単純化のため。**

------

### まとめ

- **メソッド抽出**：長いメソッドや重複コードを解消し、読みやすさを高める
- **メソッドインライン化**：不要な抽象を取り除き、直感的にする
   実際のリファクタリングでは、この2つをバランスよく使い分けることで、健全なコード構造を保てる。
