## **第30回 用观察者模式解耦事件通知**

### **1. 背景与问题**

在业务开发中，经常会遇到这样的场景：

- **用户注册成功** → 需要发邮件、加积分、记录日志
- **订单支付完成** → 需要发货、推送消息、更新库存

如果在核心业务逻辑里直接调用这些处理逻辑，就会造成：

- 代码臃肿：一个方法里调用很多后续处理
- 高耦合：新增或删除一个功能就要修改核心逻辑
- 难以维护：流程越来越复杂，测试成本增加

### **2. 重构思路**

通过 **观察者模式（Observer Pattern）**，我们可以将 **事件通知** 和 **后续处理** 解耦：

- **主题（Subject）**：维护一个观察者列表，当事件发生时，通知所有观察者。
- **观察者（Observer）**：只需关注自己感兴趣的事件，独立实现处理逻辑。

这样，核心业务代码只负责 **发出事件**，至于事件发生后执行什么，不需要关心。

### **4. 代码示例**

#### Java 示例

```
// 事件对象
class UserRegisterEvent {
    private String username;
    public UserRegisterEvent(String username) {
        this.username = username;
    }
    public String getUsername() { return username; }
}

// 观察者接口
interface Observer {
    void update(UserRegisterEvent event);
}

// 具体观察者
class EmailObserver implements Observer {
    public void update(UserRegisterEvent event) {
        System.out.println("发送欢迎邮件给 " + event.getUsername());
    }
}

class PointObserver implements Observer {
    public void update(UserRegisterEvent event) {
        System.out.println("给用户 " + event.getUsername() + " 增加积分");
    }
}

// 主题（被观察者）
class UserService {
    private List<Observer> observers = new ArrayList<>();
    public void addObserver(Observer o) { observers.add(o); }

    public void register(String username) {
        System.out.println("用户 " + username + " 注册成功");
        UserRegisterEvent event = new UserRegisterEvent(username);
        notifyAll(event);
    }

    private void notifyAll(UserRegisterEvent event) {
        for (Observer o : observers) {
            o.update(event);
        }
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        UserService userService = new UserService();
        userService.addObserver(new EmailObserver());
        userService.addObserver(new PointObserver());

        userService.register("Anna");
    }
}
```

运行结果：

```
用户 Anna 注册成功
发送欢迎邮件给 Anna
给用户 Anna 增加积分
```

#### Dart (Flutter) 示例

```
// 事件
class UserRegisterEvent {
  final String username;
  UserRegisterEvent(this.username);
}

// 观察者接口
abstract class Observer {
  void update(UserRegisterEvent event);
}

// 具体观察者
class EmailObserver implements Observer {
  @override
  void update(UserRegisterEvent event) {
    print("发送欢迎邮件给 ${event.username}");
  }
}

class PointObserver implements Observer {
  @override
  void update(UserRegisterEvent event) {
    print("给用户 ${event.username} 增加积分");
  }
}

// 被观察者
class UserService {
  final List<Observer> _observers = [];

  void addObserver(Observer observer) => _observers.add(observer);

  void register(String username) {
    print("用户 $username 注册成功");
    final event = UserRegisterEvent(username);
    for (final observer in _observers) {
      observer.update(event);
    }
  }
}

void main() {
  final userService = UserService();
  userService.addObserver(EmailObserver());
  userService.addObserver(PointObserver());

  userService.register("Anna");
}
```

### **5. 重构收益**

- **解耦**：核心逻辑与后续逻辑分离，互不影响
- **扩展性强**：新增/删除一个观察者，只需注册/注销即可，不动核心代码
- **复用性高**：不同场景下，观察者可以灵活组合

### **6. 注意事项**

- 观察者过多时可能造成 **级联通知**，要注意异步处理
- 事件总线（EventBus）、消息队列（MQ）也是观察者模式的工程化扩展
- 在 Flutter 中，可以用 **StreamController**、**ValueNotifier** 或 **Riverpod Provider** 来实现观察者模式

------

✅ **小结**：
 通过观察者模式，我们成功将“事件通知”从“核心业务”中解耦，避免了硬编码依赖，使系统更灵活、更可维护。下一回，我们将继续讨论 **第31回：命令模式与可撤销操作**，看看如何为操作引入可回溯能力。



# **第30回 オブザーバーパターンでイベント通知を疎結合にする**

------

## **1. 背景と問題**

業務開発では以下のような場面がよくあります：

- **ユーザー登録成功** → メール送信、ポイント付与、ログ記録
- **注文支払い完了** → 発送、プッシュ通知、在庫更新

もしこれらの処理をコアビジネスロジック内で直接呼び出すと：

- コードが肥大化する
- 強い結合により拡張が難しい
- テストや保守コストが増大する

------

## **2. リファクタリングの考え方**

**オブザーバーパターン（Observer Pattern）** を利用することで、イベント通知と後続処理を疎結合にできます。

- **Subject（サブジェクト）**：オブザーバーリストを管理し、イベント発生時に通知する
- **Observer（オブザーバー）**：関心のあるイベントのみ処理する

コアビジネスは **イベントを発行するだけ** で、後続処理には依存しません。
