## 1. 命名（Naming）

**核心原则：见名知意，统一规范**

- **变量/函数/类名**：应该能清晰表达用途，不要省略成让人费解的缩写。
  - ❌ `tmp`, `val1`, `doStuff()`
  - ✅ `customerList`, `maxRetryCount`, `calculateChecksum()`
- **一致性**：统一使用驼峰（camelCase）、帕斯卡（PascalCase）、蛇形（snake_case）等风格，不要混用。
- **语义化**：避免过度技术化的名字，多用领域术语。
  - ❌ `processData()`
  - ✅ `generateInvoice()`
- **前后缀规范**：布尔型通常用 `is/has/should/can` 开头。
  - ✅ `isValid`, `hasChildren`, `canRetry`

------

## 2. 注释（Comments）

**核心原则：解释“为什么”，而不是“做了什么”**

- **避免多余注释**：能通过命名看懂的内容，不要写注释。

  - ❌

    ```
    i = i + 1; // i加一
    ```

- **解释背景和意图**：注释应该解释为什么这样实现、背后的约束条件。

  - ✅

    ```
    // 使用指数退避避免对 API 网关的过度请求
    retryWithExponentialBackoff()
    ```

- **保持同步**：代码变了，注释也要改。过时的注释比没有注释更糟。

- **文档注释**：对公共 API、库函数等，使用工具生成文档的注释（如 Dart 的 `///`，Java 的 `/** */`）。

------

## 3. 可读性（Readability）

**核心原则：写给人看的代码，而不是写给机器的**

- **函数短小**：一个函数最好不超过 30 行，单一职责。

- **减少嵌套**：深层 `if/else` 或 `try/catch` 可以用早返回（guard clause）。

  - ❌

    ```
    if (user != null) {
      if (user.isActive()) {
        doSomething();
      }
    }
    ```

  - ✅

    ```
    if (user == null) return;
    if (!user.isActive()) return;
    doSomething();
    ```

- **一致缩进与格式化**：统一用代码格式化工具（Prettier、ktlint、dartfmt）。

- **分块组织**：相关代码放在一起，使用空行分隔逻辑块。

- **避免魔法数字**：用常量代替。

  - ❌ `if (speed > 88)`
  - ✅ `if (speed > SPEED_THRESHOLD)`

------

✅ **总结**：

- 命名负责“告诉你是什么”。
- 注释负责“告诉你为什么”。
- 可读性负责“让你轻松理解整体”。



## 1. 命名（Naming）

**核心原則：名前を見れば意味が分かり、規則を統一すること**

- **変数／関数／クラス名**：用途が明確に分かるようにし、省略形や意味不明な略語は避ける。
  - ❌ `tmp`, `val1`, `doStuff()`
  - ✅ `customerList`, `maxRetryCount`, `calculateChecksum()`
- **一貫性**：camelCase、PascalCase、snake_case などのスタイルを混在させず統一する。
- **セマンティック（意味的）命名**：過度に技術的な名前を避け、できるだけドメイン用語を用いる。
  - ❌ `processData()`
  - ✅ `generateInvoice()`
- **接頭辞・接尾辞の規則**：ブール値は `is` / `has` / `should` / `can` で始めるのが一般的。
  - ✅ `isValid`, `hasChildren`, `canRetry`

------

## 2. コメント（Comments）

**核心原則：「何をしたか」ではなく「なぜそうしたか」を説明すること**

- **不要なコメントを避ける**：名前から理解できる内容にはコメントを付けない。

  - ❌

    ```
    i = i + 1; // iを1増加
    ```

- **背景や意図を説明する**：なぜこの実装なのか、どんな制約があるのかを明示する。

  - ✅

    ```
    // APIゲートウェイへの過剰リクエストを避けるため指数バックオフを使用
    retryWithExponentialBackoff()
    ```

- **常に同期させる**：コードが変わればコメントも更新する。古いコメントは無いより悪い。

- **ドキュメンテーションコメント**：公開 API やライブラリ関数には、ツールでドキュメント化可能な形式（Dart の `///`、Java の `/** */`）を使用する。

------

## 3. 可読性（Readability）

**核心原則：機械ではなく人間が読むためのコードを書くこと**

- **関数は短く**：1つの関数は30行以内、単一責務が望ましい。

- **ネストを減らす**：深い if/else や try/catch を避け、ガード節（早期リターン）を活用する。

  - ❌

    ```
    if (user != null) {
      if (user.isActive()) {
        doSomething();
      }
    }
    ```

  - ✅

    ```
    if (user == null) return;
    if (!user.isActive()) return;
    doSomething();
    ```

- **統一されたインデントとフォーマット**：Prettier、ktlint、dartfmt などのフォーマッタを活用。

- **コードのブロック化**：関連するコードをまとめ、空行で区切って読みやすくする。

- **マジックナンバーを避ける**：定数で置き換える。

  - ❌ `if (speed > 88)`
  - ✅ `if (speed > SPEED_THRESHOLD)`

------

## ✅ まとめ

- 命名は **「何であるかを伝える」**。
- コメントは **「なぜそうなのかを伝える」**。
- 可読性は **「全体を理解しやすくする」**。
